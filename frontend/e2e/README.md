# Browser acceptance

Run the existing frontend on `http://localhost:3000` and backend on `http://localhost:8000`.
The tests use installed Google Chrome through Playwright; the browser extension is not required.

```powershell
cd frontend
npm run test:e2e:mocked
npm run test:e2e:auth
npm run test:e2e:live
npm run test:e2e:workspace-upload
npm run test:e2e:auth
npm run test:e2e:admin
```

For manual sign-in, run `test:e2e:auth` in an interactive terminal. If an agent's sandbox hides the window, launch that command outside the sandbox. Sign in first with an ordinary test account, then run the command again with a platform admin test account for admin checks. Passwords are entered only in Chrome. Fresh browser profiles are separate from the main Chrome profile. Sessions are stored separately in gitignored `playwright/.auth/user.json` and `admin.json`; do not commit or share them. Remove the files when testing is finished. The full suite requires both sessions; mocked tests require neither.

- `mocked.spec.ts`: real rendered frontend with explicitly intercepted API fixtures, desktop 1440×900 and touch emulation 390×844. Unknown fixture requests fail. This proves UI behavior under controlled failures and races, not backend correctness.
- `organization-provisioning.spec.ts`: `npx playwright test organization-provisioning.spec.ts` kiểm UI tạo Organization, retry idempotent, invite/suspend employee, capabilities, activation qua fragment và My Drive thuộc Organization. Chạy desktop/mobile bằng API fixtures, không dùng account thật; không chứng nhận email delivery hoặc provisioning runtime.
- `p2-hardening.spec.ts`: `npx playwright test p2-hardening.spec.ts` kiểm request/approval removal, stale response và capability denial, SaaS removal, fragment/legacy invitation scrubbing, POST preview, login continuation và paste invitation. Chạy desktop/mobile bằng fixture; không dùng token/tài khoản thật hoặc ghi dữ liệu backend phục vụ.
- `admin.spec.ts`: real read-only platform admin APIs and rendered pages, access boundaries, search, sessions dialog, quota edit capability and theme/navigation. No API mocking; observed admin API mutations fail the test. Backup/telemetry pages verify their disconnected states, not working backup or monitoring services. It does not submit quota, membership, account or settings changes.
- `live.spec.ts`: no API interception, real session and local backend/storage. The upload test creates one uniquely named 9 MiB text file, waits for completion, checks downloaded bytes, moves that exact file to Trash, then permanently removes only that verified generated fixture to release test quota. It does not change permissions or quota policy. Do not run against a personal or production account. Run the documented `run_upload_finalizer` worker before upload tests. If a test stopped while waiting for the worker, `E2E_RECOVER_UPLOAD=ui-acceptance-<timestamp>.txt` verifies and cleans up that exact prior fixture; it does not count as a fresh upload run.
- `workspace-upload.spec.ts`: real Workspace creation, two concurrent quota-admission requests (one accepted/one rejected), abort/release, browser multipart upload of a 9 MiB fixture, byte-for-byte proxy and native UI download, and private-quota isolation. Deletes only its verified generated file and archives its own empty Workspace; audit/session history remains. It uses the default small Workspace allocation (greater than 9 MiB, at most 100 MiB) and does not alter existing quota policy or membership. Run with `npm run test:e2e:workspace-upload` after ordinary-user sign-in and starting the finalizer. `E2E_AUTH_STATE` may select the approved private fixture session; run `npx playwright test workspace-upload.spec.ts` for both desktop and mobile.

- `p4-qualification.live.spec.ts`: gate opt-in P4 trên fixture mới độc lập, Next `127.0.0.1:13000`, Django `127.0.0.1:18000`, PostgreSQL riêng và ba S3 ports `18633/18643/18653`. `P4_FIXTURE_ACCOUNTS` chỉ nhận file private `/.python/p4-final-fixture/app/browser-accounts.json` đã được tạo và duyệt; không tự tìm credential hoặc dùng serving account. File chứa endpoint và các actor fixture, không được commit. Chạy `npx playwright test p4-qualification.live.spec.ts --project=desktop` rồi `--project=mobile`; `P4_FIXTURE_ACTOR_ROLE=enterprise_a_peer` hoặc `enterprise_b_employee` chọn đúng Enterprise fixture. Kiểm UI login/session/CSRF, multipart 9 MiB, AVAILABLE trước UI success, native signed download đúng bytes/version/endpoint, rename/move/share/trash/restore; không mock API/storage. Giữ file và receipt private để kiểm persistence/restore, vì vậy không chạy lặp khi chưa đối chiếu quota/receipt. Không có fixture thì **SKIP**, không phải provider PASS. Xem [qualification report](../../docs/PLATFORM_QUALIFICATION_2026-11-13.md) cho môi trường, kết quả và giới hạn recovery.

- `download.spec.ts`: native navigation fixtures, attachment-based Unicode filename, no Blob, no application cookies or Workspace headers, explicit backend compatibility, authorization failure, browser-owned expired/network errors, fresh-ticket retry, unsafe URLs, multiple files, item action menu, toolbar and folder ZIP. Run `npm run test:e2e:download` for desktop and mobile. The current product has a three-dot `ContextMenu` component, not a row right-click handler; the test uses that existing menu.
- `presigned-download-live.spec.ts`: requires ordinary-user sign-in, running finalizer, migration 0016, versioned storage with a scoped application identity, a browser-reachable signing endpoint isolated from application cookies, `SECUREDRIVE_DIRECT_DOWNLOAD_ENABLED=true` and `E2E_PRESIGNED_DOWNLOAD=1`. Creates its own Workspace and 16 MiB file; after the real API signs a version, overwrites only that generated fixture with different bytes at the same key/size. Native GET must still return the original bytes/SHA-256 and attachment name, with no binary proxy or false completed/progress. Verifies anonymous denial, then purges both versions and staging, releases quota and archives its own empty Workspace. The test invokes the repository Python environment for its exact generated fixture only; it does not change existing files, permissions, credentials or quota policy. With test API TTL at most ten seconds it also checks expired-URL denial. Run `npm run test:e2e:download-live`. Optional local `E2E_DOWNLOAD_API_URL` routes authorization to a separately configured real Django process; it does not mock the response. Normally leave it unset. Local scoped IAM, version pinning and rollout were verified on 08/11/2026; see the download report for production limits.

Use `npm run test:e2e -- --project=desktop` to run all suites together after both sign-ins, or `npm run test:e2e` for both viewport projects. `E2E_BASE_URL` and `E2E_API_URL` support other local ports only; frontend API configuration must match.

Results and screenshots are in gitignored `test-results/`, and the HTML report in `playwright-report/index.html`. Each run replaces its output directory. Traces and video are disabled to avoid recording credentials or signed storage URLs. Screenshots can contain account/file names; treat live artifacts as private. Mobile emulation does not replace physical-device or screen-reader testing.

`npx playwright test storage-connections.spec.ts` checks the shared S2 Platform/Organization interface with intercepted fixtures only: approved-profile registration, read check, exact 64-byte browser SHA-256, recovery after failed browser GET and reload, explicit confirmation/binding while routing stays off, Organization view-only scope, flag-off fallback, navigation selection and dark 320px layout. It never creates a real bucket or uses saved authentication. Real MinIO acceptance remains a separate operator-approved LAB gate in the S2 runbook.

`npx playwright test storage-topology.spec.ts` checks S3 with intercepted inventory: position-only saves/reload/conflict/discard, keyboard list/inspector focus, scoped disk data, stale/error/empty states, oversized snapshot pagination, mouse and CDP-emulated touch dragging, dark320px and720px viewport equivalent to desktop200% zoom. The100-node test records browser inspector latency and45 rAF intervals during wheel pan, with API requests bounded independently of node count. This is a local Chrome fixture benchmark; it is not physical-device testing, native browser zoom-control verification or live host telemetry. The report keeps the measured values and limitations.

`npx playwright test storage-monitoring.spec.ts` checks S4 with explicit monitoring fixtures: last-known stale values and position preservation on network error, clock-based sample expiry, Organization node metrics and acknowledged-but-active incidents, native EventSource resync, unconfigured monitoring and clearing measurements after403. Desktop/mobile both run; S3 and S4 share the inventory fixture. No saved sign-in, real exporter, provider credentials or real collector are used. ASGI stream authorization/revocation is independently tested against the backend on isolated PostgreSQL; reverse-proxy/load behavior remains a real G4 acceptance task.
